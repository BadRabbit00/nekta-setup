# Границы работ

Плейбуки выполняют **только то, что предписано документацией Nekta**
(«Подготовка к установке» и «Системные требования»), плюс настройку ИБП с
USB-интерфейсом по отдельному требованию заказчика.

Этот документ существует, чтобы через полгода никто — включая нас — не начал
дописывать сюда «полезное». Всё, чего нет в документации вендора, добавляется
только по явному решению, и тогда же дополняется этот файл.

## Что делают плейбуки и на каком основании

| Действие | Основание в документации |
|---|---|
| Проверка процессора, ОЗУ, дисков, сети | «Системные требования», профиль до 10 000 устройств |
| Расчёт объёма диска хранения | «Расчёт объёма жесткого диска (HDD) для хранения данных» |
| Проверка исходящего доступа к ресурсам вендора | «Подготовка к установке», п. 2 |
| Открытие портов 22, 80, 81, 443, 4443, 3003, 6060/tcp, 1600/udp | «Подготовка к установке», п. 3 |
| Открытие 82/tcp только для адресов техподдержки | «Подготовка к установке», п. 3 |
| Проверка версии ОС | «Подготовка к установке», п. 4 |
| Монтирование диска 2 в `/nekta` | «Диск 2 (хранение) необходимо монтировать на директорию /nekta» |
| RAID1 из двух HDD на сервере копий | «Диск 2 (Хранение): RAID1 из 2хHDD» |
| Проверка правила «объём копий ≥ 3× объёма дисков» | «Минимальные системные требования к серверу резервного копирования» |
| Сбор сведений для техподдержки | «Подготовка к установке», п. 5 |
| ИБП: драйвер, мониторинг, выключение | Требование заказчика, вне документации Nekta |

## Чего плейбуки не делают

**Nekta Server не устанавливается.** Его ставит вендор по SSH. Документация
требует передавать «чистую» ОС без дополнительных компонентов, поэтому
плейбуки не ставят docker, СУБД и вообще ничего, что не нужно для
перечисленных выше задач.

**Программное обеспечение резервного копирования не настраивается.**
Документация Nekta описывает для сервера копий только характеристики железа:
процессор, ОЗУ, диски, RAID1, объём, скорость сети. Ни процедуры копирования,
ни утилит, ни указания, кто это настраивает, в ней нет. Плейбук готовит
железо — массив и том — и на этом останавливается.

Что делать дальше с сервером копий, стоит выяснить у техподдержки Nekta
(support@nekta.tech): есть ли у вендора штатная процедура резервного
копирования и что именно необходимо сохранять. До получения ответа копии не
снимаются — и об этом нужно знать явно, а не обнаружить при аварии.

**Настройка ОС не выполняется.** Ни синхронизации времени, ни лимитов ядра,
ни параметров sysctl, ни автообновлений, ни контроля S.M.A.R.T., ни почтовых
уведомлений, ни усиления SSH: в документации Nekta этого нет. Часть из
перечисленного полезна и может быть добавлена позже — но отдельным решением,
а не «заодно».

## Порядок работ

1. `playbooks/preflight.yml` — проверка железа и сети, ничего не меняет.
2. `playbooks/site.yml` — подготовка обоих серверов.
3. Передача доступа вендору ([05-handover.md](05-handover.md)), установка
   Nekta Server силами вендора.
4. `playbooks/ups.yml` — настройка ИБП.

ИБП настраивается **после** установки Nekta Server: NUT — это дополнительные
пакеты, а на момент установки ОС должна быть чистой.
