# Сеть: порты, исходящий доступ, docker и ufw

## Входящие порты сервера Nekta

Роль `firewall` открывает их по списку из `inventory/group_vars/nekta.yml`.
Столбец «переназначение» — требование вендора, а не рекомендация: порты,
помеченные «нельзя», зашиты в клиентскую часть и веб-интерфейс.

| Порт | Протокол | Назначение | Переназначение |
|---|---|---|---|
| 22 | TCP | SSH: установка, обновление, диагностика | можно |
| 80 | TCP | Веб-интерфейс, HTTP | можно |
| 81 | TCP | Веб-интерфейс | **нельзя** |
| 443 | TCP | Веб-интерфейс, HTTPS | можно |
| 4443 | TCP | Веб-интерфейс, HTTPS | **нельзя** |
| 3003 | TCP | Push-уведомления в интерфейсе | **нельзя** |
| 6060 | TCP | Веб-интерфейс сетевого сервера LoRaWAN | можно |
| 1600 | UDP | Приём данных с базовых станций LoRaWAN | можно |
| 82 | TCP | Отладка и диагностика | открыт только для адресов поддержки |

Для HTTPS нужны одновременно 80, 81, 443 и 4443 — 80 участвует в выпуске и
продлении сертификата.

При использовании шлюзов GPRS, NB-IoT или Ethernet добавляются порты,
зависящие от модели оборудования; их список даёт вендор.

## Исходящий доступ

Установка и обновление идут из интернета, поэтому серверу нужен доступ к:

| Ресурс | Порт |
|---|---|
| 217.113.124.240 | 443 |
| 84.201.166.187 | 8000 |
| docker.nekta.cloud (все поддомены) | 443 |
| ppa.launchpad.net | 443 |
| archive.ubuntu.com, ru.archive.ubuntu.com | 80 |

Проверка выполняется автоматически при каждом прогоне и отдельно командой:

```bash
ansible-playbook playbooks/preflight.yml
```

Недоступный ресурс попадёт в вывод отдельным предупреждением.

## Требования вендора к доступу

- **SSH на время установки и обновления должен быть доступен из интернета.**
  Через VPN вендор не работает. После сдачи системы порт можно закрыть, но
  открывать обратно придётся на каждое обновление и разбор инцидента.
- Если доступ ограничивается по IP, открывайте для `217.113.124.240` и
  `84.201.166.187`.
- При работе только в локальной сети достаточно 22/TCP на время установки.

Ограничить SSH сетями управления:

```yaml
firewall_restrict_ssh_to_management: true
site_management_networks:
  - "10.0.0.0/24"
  - "217.113.124.240/32"   # не забудьте поддержку, иначе обновление встанет
```

## Пароль SSH для передачи вендору

Вендор просит логин и пароль. В его памятке есть неочевидное требование к
символам — часть спецсимволов ломает их инструменты автоматизации:

```
рекомендуемые:     ! @ * ( ) — _ + =
нерекомендуемые:   » # $ % & ' , . / : ; < > ? [ \ ] ^ ` { | } ~
```

Поэтому в `inventory/group_vars/nekta.yml` парольная аутентификация оставлена
включённой (`common_ssh_password_authentication: true`). После сдачи системы
переведите доступ на ключи, вернув `false`.

## Docker обходит ufw — и это не ошибка настройки

Публикуя порт (`-p 8080:80`), docker добавляет правила в собственные цепочки
iptables, которые обрабатываются **раньше** правил ufw. В результате
опубликованный контейнером порт доступен снаружи, даже если `ufw status`
показывает его закрытым. После установки стека Nekta вендором это станет
заметно: контейнеры опубликуют свои порты мимо ufw.

Штатная точка вмешательства — цепочка `DOCKER-USER`, которую docker
просматривает первой. Роль `firewall` заранее кладёт:

- `/usr/local/sbin/nekta-docker-firewall` — идемпотентно применяет правила;
- drop-in для `docker.service` (`ExecStartPost`), чтобы правила применялись
  автоматически при каждом запуске docker — в том числе после того, как его
  установит вендор;
- `/etc/nekta/docker-firewall.conf` — список разрешённых источников.

По умолчанию ограничение **выключено** (`RESTRICT=no`): веб-интерфейс Nekta
должен быть доступен пользователям. Включать имеет смысл, когда система
работает только в локальной сети:

```yaml
firewall_restrict_docker_ports: true
firewall_docker_allowed_sources:
  - { port: 443, proto: tcp, source: "10.0.0.0/8" }
  - { port: 80,  proto: tcp, source: "10.0.0.0/8" }
```

Проверка:

```bash
nekta-docker-firewall show     # текущие правила цепочки
nekta-docker-firewall apply    # применить заново
ufw status verbose             # правила для трафика к самому хосту
```

Если docker ещё не установлен, скрипт сообщает об этом и завершается без
ошибки — цепочки `DOCKER-USER` пока не существует.
