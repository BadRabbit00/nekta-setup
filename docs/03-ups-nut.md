# ИБП с USB: драйвер, настройка, проверка

Обслуживанием ИБП занимается **NUT (Network UPS Tools)**. Кабель USB идёт от
ИБП к одному серверу, второй узнаёт состояние питания по сети.

```
   ИБП ──USB──► nekta-01 (netserver)  ──сеть, порт 3493──►  backup-01 (netclient)
                 драйвер usbhid-ups                          upsmon
                 upsd (раздаёт состояние)
                 upsmon + upssched
```

Почему так: драйвер общается с ИБП напрямую через USB, и подключить второй
сервер к тому же кабелю нельзя. `upsd` на сервере ИБП раздаёт состояние по
сети, `upsmon` на клиенте его читает и выключает свою машину по команде.

## Настройка в инвентаре

Кто к чему подключён, задаётся `nut_mode`:

```yaml
# inventory/group_vars/nekta.yml
nut_mode: "netserver"     # сюда воткнут USB-кабель

# inventory/group_vars/backup.yml
nut_mode: "netclient"     # состояние приходит по сети
```

Если кабель воткнут в сервер копий — поменяйте значения местами, остальное
подстроится само: `nut_server_host` вычисляется из инвентаря.

Пароли обязательны и берутся из vault:

```yaml
vault_nut_admin_password: "..."
vault_nut_monitor_password: "..."
```

Без них роль остановится с понятной ошибкой, а не создаст ИБП с пустым
паролем, доступный всей подсети.

## Подбор драйвера

По умолчанию — `usbhid-ups`, он покрывает большинство ИБП с USB (APC,
Eaton, CyberPower, Ippon, Powercom, Systeme Electric). Если ИБП говорит по
протоколу Megatec/Q1, нужен `nutdrv_qx`.

Определить модель на сервере:

```bash
lsusb
nut-scanner -U          # выводит готовый блок для ups.conf
```

Вывод `nut-scanner` подставляется в `inventory/host_vars/nekta-01.yml`:

```yaml
nut_ups_driver: "usbhid-ups"
nut_ups_port: "auto"
nut_ups_vendorid: "051d"      # если ИБП несколько или драйвер цепляет не тот
nut_ups_productid: "0002"
```

При заданном `nut_ups_vendorid` роль дополнительно кладёт правило udev — оно
нужно, когда модель не описана в штатном `62-nut-usbups.rules` и драйверу не
хватает прав на устройство.

## Что происходит при отключении питания

| Время от пропадания питания | Событие |
|---|---|
| 0 с | `ONBATT`, запись в журнал, сообщение на терминалы |
| 30 с (`nut_on_battery_warn_delay`) | письмо дежурной службе — короткие провалы никого не будят |
| 300 с (`nut_on_battery_shutdown_delay`) | сервер ИБП объявляет `FSD`: клиенты начинают выключаться |
| +до 30 с (`nut_host_sync`) | сервер ИБП ждёт отключения клиентов |
| далее | останавливаются контейнеры Nekta, затем гасится система |

Выключение по таймеру, а не по сигналу «батарея разряжена», выбрано осознанно:
к моменту `LB` заряда может не хватить на корректную остановку СУБД, а
незакрытая база — это как раз тот случай, когда придётся восстанавливаться из
резервной копии. Порог меняется одним параметром:

```yaml
nut_on_battery_shutdown_delay: 600   # 0 — выключаться только по сигналу LB
```

### Остановка стека перед выключением

`SHUTDOWNCMD` вызывает `/usr/local/sbin/nekta-ups-shutdown`, который сначала
останавливает контейнеры (`docker stop -t 90`), даёт СУБД сбросить буферы и
только потом гасит систему. На сервере, где docker ещё не установлен вендором,
шаг просто пропускается.

## Проверка

```bash
ansible-playbook playbooks/ups-test.yml
```

Вручную на сервере ИБП:

```bash
upsc ups0@localhost                    # все параметры
upsc ups0@localhost ups.status         # OL — от сети, OB — от батареи, LB — разряд
upsc ups0@localhost battery.charge
systemctl status nut-server nut-monitor
```

С клиента:

```bash
upsc ups0@192.0.2.10 ups.status        # должно отвечать так же
```

Не отвечает — проверьте по порядку: `lsusb` видит ИБП, служба `nut-server`
запущена, порт 3493 открыт для клиента (`ufw status`), в `upsd.users` есть
пользователь `upsmon` с тем же паролем, что в `upsmon.conf` клиента.

### Проверка сценария выключения

Полная проверка — единственный способ убедиться, что сервер действительно
переживёт отключение света. Проводите её в согласованное окно.

```bash
# 1. «Сухая» проверка: имитация события без выключения
upsmon -c fsd --help          # убедитесь, что понимаете команду ниже

# 2. Реальная проверка: выдернуть питание ИБП из розетки
#    и наблюдать журнал на обоих серверах
journalctl -fu nut-monitor -t nekta-ups -t nekta-ups-shutdown
```

Ожидаемое: через 30 с приходит письмо, через 300 с сервер копий выключается
первым, затем сервер Nekta останавливает контейнеры и гасится.

После восстановления питания ИБП сам подаёт напряжение; автоматическое
включение серверов настраивается в BIOS (`Restore on AC Power Loss: Power On`)
— NUT на это повлиять не может.

## Замена батареи

`upsmon` следит за флагом `RB` и присылает письмо «Требуется замена батареи».
Игнорировать его не стоит: изношенная батарея держит нагрузку секунды, и
таймер на 300 с превращается в отключение без предупреждения. Ресурс —
ориентировочно 3–5 лет.

```bash
upsc ups0@localhost battery.runtime    # остаток автономии в секундах
upsc ups0@localhost battery.date
```
